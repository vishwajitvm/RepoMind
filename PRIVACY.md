# RepoMind — Privacy & Data Handling Policy

**Last Updated:** September 2026  
**Effective Date:** September 2026

RepoMind ("we", "our", or "the platform") is an AI-powered codebase intelligence system. We recognize the critical importance of keeping proprietary source code, credentials, intellectual property, and engineering knowledge private and secure.

This Privacy & Data Handling Policy outlines how RepoMind handles your source code, queries, embeddings, credentials, and telemetry data.

---

## 1. Core Privacy Guarantees

1. **Your Code Remains Yours**: You retain 100% ownership and copyright of all source code, queries, and generated analysis. RepoMind does not claim any rights over the repositories you index.
2. **Minimal Data Egress**: RepoMind never sends your entire repository to an LLM. Only small, semantically retrieved code chunks (top-$k$ relevant symbols) necessary to answer specific questions are sent in prompt payloads.
3. **No Model Training**: None of your proprietary source code, AST chunks, or developer questions are used to train foundational AI models.
4. **Local & Air-Gapped Options**: RepoMind supports fully local vector storage (Qdrant), local relational storage (PostgreSQL), local embeddings (FastEmbed / Ollama), and local LLM inference (Dockerized Ollama), enabling a completely air-gapped deployment with zero external network transmission.
5. **Zero Tracking / Analytics**: RepoMind contains no tracking beacons, third-party analytics scripts, marketing trackers, or tracking cookies.

---

## 2. Information We Process

### 2.1 Repository & Source Code Data
When you register and index a repository, RepoMind processes:
- **Repository Identifiers**: GitHub repository full name (e.g., `owner/repo`), default branch, and commit hash.
- **Source Code Files**: Source code files in supported programming languages (Python, TypeScript, JavaScript, Go, Rust, Java, C++, etc.).
- **AST Chunks & Symbols**: Code structure elements such as functions, classes, interfaces, and methods identified during code-aware chunking.
- **Vector Embeddings**: Mathematical vector representations generated from code chunks and stored in your dedicated Qdrant vector collection.

### 2.2 Sensitive Files Excluded by Default
RepoMind automatically scans for and discards files matching sensitive patterns prior to AST parsing:
- Environment and configuration files: `.env`, `.env.*`, `credentials.json`, `config.secret.*`.
- Private keys and certificates: `id_rsa`, `id_ed25519`, `*.pem`, `*.key`, `*.pfx`, `*.crt`.
- Build artifacts and dependency trees: `node_modules/`, `.git/`, `dist/`, `build/`, `.venv/`, `vendor/`, `coverage/`.

### 2.3 User Inquiries & Intelligence Responses
- Natural language questions submitted via the chat interface.
- Execution plans and tool invocations generated by the LangGraph orchestrator.
- Synthesized answers, code citations, and line references.

## 3. Data Storage & Infrastructure Boundaries

RepoMind is designed to run in an isolated environment containerized via Docker:

| Data Layer | Storage Engine | Location | Description |
|:---|:---|:---|:---|
| **Relational Data** | PostgreSQL | Local Docker Container (`repomind-postgres`) | Repositories, indexing job statuses, chat history, and execution trace records. |
| **Vector Payloads** | Qdrant | Local Docker Container (`repomind-qdrant`) | Vector embeddings, file paths, line ranges, and semantic code snippets. |
| **Task Queue** | Redis | Local Docker Container (`repomind-redis`) | Ephemeral asynchronous indexing task management. |
| **Telemetry & Traces** | TraceNest | Local Filesystem (`backend/TraceNestLogs/`) | Application-level execution logs with automated regex secret redaction. |

No cloud databases or hosted vector instances are required. All indexing data resides within the containers and volumes managed on your host or private server.

---

## 4. AI Provider Interactions & Data Transmission

### 4.1 External LLM Providers
When external providers are configured (e.g., Google Gemini, Groq, NVIDIA NIM, OpenRouter):
- Only the specific code chunks retrieved from Qdrant matching the user's inquiry are forwarded in the system context.
- Requests are transmitted via TLS/HTTPS.
- Provider APIs are accessed using your own API keys configured in `backend/.env`. RepoMind does not operate a centralized proxy or store your keys remotely.
- In accordance with enterprise API data policies (such as Google Cloud Vertex AI/Gemini API and Groq Enterprise Terms), customer data submitted via API endpoints is not retained or used to train third-party foundation models.

### 4.2 Local Inference (100% Private Mode)
For complete data isolation, you can configure RepoMind to operate exclusively with:
- **LLM**: Dockerized Ollama (`repomind-ollama`) running locally with open-weight models (e.g., Llama 3, Qwen 2.5, DeepSeek Coder).
- **Embeddings**: Local embedding models via FastEmbed or Ollama.
- **MCP**: Local GitHub MCP server running within the container network.

In this configuration, **zero bytes** of source code or queries leave your infrastructure.

---

## 5. Security & Credential Hygiene

- **API Keys**: Stored solely on the backend (`backend/.env`) and never exposed to the frontend browser bundle.
- **Log Masking**: TraceNest automatically redacts authorization headers, API keys, passwords, and sensitive tokens matching security patterns.
- **Read-Only GitHub Boundary**: GitHub integration operates under a strict read-only security boundary. RepoMind cannot push code, modify branches, or delete repository assets.

---

## 6. Data Retention & Deletion

- **Relational & Vector Data**: You can permanently delete indexed repository data and vector points at any time by removing the repository via the RepoMind API (`DELETE /api/repositories/{id}`) or by resetting the Docker volumes (`docker compose down -v`).
- **Telemetry Logs**: TraceNest automatically manages log file retention and rotation according to configured policies (default 30 days).
